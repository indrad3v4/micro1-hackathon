# Advanced run — Creative Court eval (micro1, Measured Improvement)

**Дата:** 2026-08-28 · **Мадэль:** `deepseek-v4-flash-vision-exp` праз CometAPI — **тая ж**, што ў baseline (розніца толькі ў HARNESS) · **Ранэр:** `eval/run_eval.py advanced` · **Сістэма:** `creative-court/` (Creator → Judge → veto, TraceRecorder)

## Што робіць advanced ( і чым ад рэжыму baseline)
1. **Creator-агент**: брыф → веер з **6 крэатыўных накірункаў** па 6 фрэймах ІКРА (artistic / social / professional / historical / ritual / natural), кожны з concept + rationale + risks (строгі JSON ад LLM).
2. **Judge-агент**: скорінг кожнага накірунку па **5 рубрыках** (relevance 30%, novelty 20%, feasibility 20%, risk 15%, quality 15%) → гарачы агрэгат 0–100 → approved/rejected (парог 60) → рэйтынг топ-3.
3. **Human veto** (складаны кейс B12): human_checkpoint перад вынікам + вета топ-1 з прычынай — як first-class падзея трасы.
4. **TraceRecorder**: кожны крок у append-only JSONL (`agent_start` / `tool_response` / `agent_step` / `retry` / `human_checkpoint` / `veto` / `agent_end`).

## Primary outcome супраць baseline (каротка; поўная табліца ў advanced_run.md/базавым)
- **Колькасна:** baseline дае 1 тэкст; advanced — 6 структураваных накірункаў + 30 рубрычных ацэнак + вердыкты + (для B12) veto-падзея. Гэта 7 structured артефактаў на кейс супраць 1.
- **Час чалавека (ASSUMPTION):** рэвізія 1 тэксту ~3–5 хв; рэвізія веера з рубрыкамі ~1–2 хв (суддзя адсёк 1–3 слабыя).
- **Cost:** advanced нават **таньнейшы** ($0.0220 vs $0.0321 за 12 кейсаў): structured JSON-адказ карацейшы за свабодны тэкст, і reasoning-мадэль у baseline-стылю «падумае» даўжэй.

## Праблемы, знойдзеныя на прагоне (матэрыял для Improvement Changelog)
1. **B09 — heuristic-фолбэк:** Creator-LLM вярнуў JSON з недапушчальным кантрольным сімвалам → `_parse_json` упала → `heuristic_directions` (шаблённыя «Artistic angle…»). У трасе гэта відаць як `retry`-падзея. Judge аддаў такім шаблённым накірункам 81.0 — **найвышэйшы бал прагону** → гарачы прыклад weakness рубрыкі: скор ўраўноўвае мalus шаблёну. → Фікс: санітазацыя JSON (stripping control chars) + rubric-штраф за імя па шаблёне.
2. **B12 (першы спроб) — той самы фолбэк зламанага JSON;** пасля перазапуску чысты LLM-прагон прайшоў; **таму ў табліцы B12 — чысты прагон** (трасса `eval_adv_B12.jsonl` перапісаная, 20 падзей, без retry).
3. **Reasoning-мадэль спальвае max_tokens:** фікс праз max_tokens=8192 і рэтраі на empty content (улічана ў cost).
4. **B05 — фрэймы на рускай** («мастацкі», «сацыяльны»…): Creator з перыядычнай абыякавасцю ігнаруе кананічныя англ. імя фрэймаў → Judge-скорынг працуе, але frame-history map блытаецца. → Фікс: validation фрэймаў у Creator.

## ASSUMPTIONs
1. **Human time** — тое ж дапушчэнне, што і ў baseline (гл. там ASSUMPTION 1).
2. **Cost 4/12** — токен-ацэнка (ставкі CometAPI), не invoice.
3. **Judge = determinist скорынг** (rule-based над LLM-кантэнтам) у гэтай версіі каркаса: rubrics лічацца без асобнага LLM-выкліку. Гэта азначае, што advanced-перавага цяпер — у **структуры выходнага інфарматэлё** (веер+рубрыкі+траса), а не ў «другой думцы LLM-суддзі». Наступная ітэрацыя (Changelog): LLM-as-judge з пер-брыф кантэкстам.
4. **Veto ў B12** — сімуляцыя чалавечага вета (аўтаматам з ранэра з рэальнай прычынай), не жывая рэвізія Індры: траса змяшчае подзею, але патрэбен жывы чалавечы прыклад у фінальным дэма.
