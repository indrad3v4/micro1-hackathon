Every trajectory is **append-only JSONL** written by `TraceRecorder`
(`creative-court/src/creative_court/core/trace.py`) with atomic per-line `fsync`.
Each line is one flat event. The four submission-required aspects map directly
onto schema fields:

| Requirement | Schema field(s) |
|---|---|
| instruction | `instruction` |
| action | `action` / `tool` / `tool_response` |
| feedback | `feedback` |
| human checkpoints | `type: "human_checkpoint"` + `human_checkpoint` |

**12-key schema** (per line):

```jsonc
{"ts": "…ISO-8601 UTC…", "agent": "creator|judge|harness|…",
 "type": "agent_start|agent_step|agent_end|tool_call|tool_response|veto|retry|human_checkpoint",
 "instruction": "…", "action": "…", "tool": "…", "tool_response": "…",
 "feedback": "…", "retry_of": "…", "human_checkpoint": "…", "verdict": "…", "data": {…}}
```

## Trace coverage honesty (from README §6, reproduced here)

- **Benchmark traces contain zero `human_checkpoint` events by design:** `run_benchmark.py`
  is a *headless* harness — no human reviews during an automated run.
- Human-checkpoint capability lives in the interactive path: the schema field, the
  `human_checkpoint` event in `agents/eval_adv_B12.jsonl`
  (`ASSESSMENT: человек проверяет топ-3 перед запуском`) and the `dashboard/` traces.
- Baseline bench traces carry **no `tool_call`/`tool_response` events because the
  baseline makes 0 LLM calls** — the absence *is* the measured zero.
- Advanced bench traces carry `tool_response` (LLM verdicts), `veto` (17 in
  `benchmark/`) and `retry` (25) events — the 10/10 drift-catch result is auditable
  event-by-event.
- Trace files are **append-only** — later interactive runs append to the same files,
  so `trace.total_events` in `final_report.json` is the snapshot at report time
  (2026-08-29T06:47Z) while committed files may hold more lines.
